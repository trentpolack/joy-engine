# Input
The runtime shell (`joy-app`) supplies `InputManager` (`joy-input`) through `frame.input`. Keyboard bindings use `KeyboardEvent.code` names, gamepads use the standard W3C mapping, and native gamepads use gilrs. Games consume the same actions and axes across targets.

Read `pressed(name)` for discrete actions each frame. For menus and grid movement, declare repeat on the action instead of timing it in the game: register `InputAction::new(bindings).repeat(DEFAULT_REPEAT_DELAY_SECONDS, DEFAULT_REPEAT_INTERVAL_SECONDS)` (fire on the press, then every 1/30 second once held for half a second) with `InputMap::action_with`, and react to `action(name).repeats`, which counts the action's fires this frame (one on the press, including a tap shorter than a frame, then one per interval). The shell passes each frame's elapsed seconds to `InputManager::update(elapsed_seconds)`. Repeat timing resets wherever holds release: `clear`, focus and visibility changes, text entry, rebinding, and context changes. Actions combine their bindings; axes choose the stronger digital or rescaled analog value. `InputBinding::stick_direction(GamepadStick::Left, StickDirection::Up)` lets a stick drive a navigation action like a d-pad: it holds when the stick's dominant axis points that way past `STICK_DIRECTION_THRESHOLD` (0.5 after the dead zone), so diagonals resolve to their stronger axis and one repeating action serves keys, the d-pad, and the stick. The default analog dead zone is 0.15. `set_contexts` selects active action contexts, and `rebind` changes bindings without changing game rules.

Focus loss, hidden windows, and egui text entry release gameplay input. Gamepads must return to neutral before reactivating. Touch input exposes individual points and stable finger IDs so simultaneous controls can track different touches. Touches also hold the primary pointer button.

Use `Frame::set_pointer_lock(true)` for mouse steering; browsers require a user gesture. `pointer_motion` reports raw frame movement in logical pixels while locked, and `pointer_locked` reports current ownership. The platform can release the lock at any time. Games own coordinate projection, on-screen control layout, and mapping actions into gameplay intent.
