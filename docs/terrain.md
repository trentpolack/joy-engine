# Streamed Quadtree Terrain
Terrain data lives in `joy-terrain` (`joy_engine::terrain`), a foundation crate shared by the renderer, physics, and gameplay. An authored heightfield becomes a tile pyramid: each coarser level decimates the one below it, so every coarse sample is an authored sample and the same edit applies identically at every level. A `TerrainStreamer` keeps the tiles that views and collision regions need resident within a budget, loading them from memory, from package files natively, or over HTTP in browsers, and publishes immutable `TerrainSurface` snapshots.

The renderer draws a surface's resident tiles with quadtree continuous LOD: tiles subdivide where their screen-space error needs it, children never draw coarser than their parent's level (so subdivision never pops), neighbors differ by at most one level, and shared edges morph identically on both sides. Tiles upload once into a pooled texture array; every backend, WebGL 2 included, takes the same path. A one-level pyramid selects exactly like the version 1 fixed leaves.

Below the authored resolution, `TerrainDetail` synthesizes more levels: a smooth Catmull-Rom reconstruction of the authored samples plus deterministic noise octaves whose amplitude and character follow the material under them (rock rough and ridged, ground gentle, snow nearly smooth), using the same slope and height rules the shader colors with. Detail is gameplay data: gameplay sampling (`TerrainSurface::height_at`) and `physics::TerrainColliders` read the collision level, never camera-selected topology. `TerrainCrater` edits are small additive operations that apply to every level, to tiles loaded later, and exactly at detail resolution.

See the [terrain implementation guide](rust-terrain.md) for the APIs, formats, and limits, and the [terrain example](../examples/terrain/README.md) for streaming Dragon Pit, craters, and props.
