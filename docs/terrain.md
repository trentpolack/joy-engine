# Resident CLOD Terrain
Joy exposes `loadTerrain`, `decodeTerrain`, `sampleTerrain`, `selectTerrain`, `reconcileTerrainEdges`, `sampleMorphedHeight`, and `TerrainRenderer`. The [terrain example guide](../examples/terrain/README.md) specifies asset version 1, offline conversion, units/orientation, render-pass ownership, backend behavior, and collision, road, and environment integration boundaries.

`RenderScene.createTerrain()` creates scene-owned presentation state that borrows the terrain asset. The scene node participates in hierarchy transforms, culling, casting, and receiving policy. `SceneRenderer` retains one device-specific adapter per live terrain node and releases it when the node leaves the scene or the renderer is destroyed.

Terrain height samples, the shared patch grid, LOD descriptors, and indirect commands remain resident GPU resources. Frame preparation updates only camera selection data and transforms; it never expands the heightfield into the CPU mesh triangle queues. The same indexed and continuously morphed surface is recorded into scene color and depth, light-space shadows, normal/roughness surfaces, and motion attachments. Static terrain motion includes camera and hierarchy-transform changes; LOD morphs intentionally use the current surface for both temporal positions so selection changes do not create false world motion.
