## Findings
1. **Runtime material interpretation gap.** `SceneRenderer` draws vertex color and instance tint/roughness; `MeshAsset.materials` and `triangleMaterials` survive compilation/baking but do not drive runtime PBR. Minimal asset: `param finish = materialPbr(rgba(1,0,0,1),0.8,0.2) instance(meshBox(1,1,1),vector(0,0,0),vector(0,0,0),vector(1,1,1),finish)`. Put `createFormMeshAsset(source)` directly in `RenderScene`: the cube renders neutral unless presentation tint is supplied. The example's local material-group adapter supplies that supported tint/roughness. Full material rendering is broader work; no engine runtime changes were made.
2. **Integer metadata is UI guidance.** `param n = 2 meta(min=1,max=5,step=1)` with override `{n:2.5}` followed by `repeat n as i {point(i,0,0)}` fails at line 2, column 1: `Expected an integer between 0 and 150000.` The building explicitly floors its floor count. Roof shape is a thresholded scalar; FORM does not provide a typed enum parameter here.
3. **No boolean `or` operator.** `if(1 or 0) {point(0,0,0)}` fails at line 1, column 6: `Expected ')', found 'or'.` The script uses a numeric predicate for the combined facade condition. This is an unsupported language feature, not a proposed compiler rewrite.
4. **Realization has a scaling cost.** Source reuse via `instance()` expands vertices, and the scene adapter owns four material-group assets. The maximum shell evaluates in ~8–9 ms, then immutable copies/group preparation add ~12–14 ms in Chrome. Regeneration is synchronous; rapid changes to significantly larger assets may require the existing worker workflow. These measurements are CPU timings, not GPU execution or an FPS guarantee.
5. **Repository validation is blocked by extraction tooling.** JoyGames `npm run check` fails immediately because `scripts/quality/check-javascript.mjs` is absent. Its script still names the old `joy-editor/` paths. `npm run validate` stops at that check; no all-game build/capture claim is made. The task did not repair root tooling or touch active games.

FORM LAB authoring worked, but its development server also logged font requests outside Vite’s serving allow list: `JoyGames/node_modules/@fontsource/...` was excluded while `joy-engine/` was allowed. Screenshots therefore use fallback fonts. Minimal reproduction: run the hosted FORM LAB dev command and inspect font network responses. This is another extraction/hosting limitation; no editor changes were made.

## Unsupported Houdini-like capabilities
This asset exposes a source recipe plus parameter snapshots and deterministic recooking. It does not provide a node graph, live external DCC bridge, booleans for openings, production UV unwrapping, automatic LOD/collision/navmesh outputs, dependency scheduling, or shared GPU instancing. Window/door panels are deliberately opaque facade details. Primitive UVs exist but are not a building texture layout. FORM supports named geometry/logical-instance outputs elsewhere; this legacy-instance exercise does not consume them. Empty named output lists here are expected. Geometry and semantic entrance metadata remain reusable, but no claim of a production Houdini Engine replacement is made.
