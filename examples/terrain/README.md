# Terrain example
This npm workspace is a developer example, excluded from the main site and automatic release builds/captures. Root checks and tests still include it. Dragon Pit is a resident landscape experiment for Joy's roughness-adaptive indexed terrain pass. Run `npm run dev:example:terrain` from the root; build with `npm run build:example:terrain`. Add `?backend=webgl` or `?backend=webgpu` to select a backend explicitly. The default prefers WebGPU and falls back to WebGL 2. Left-drag (a one-finger trackpad press and drag) orbits around the current focus. Scroll with two fingers to zoom. Hold right-click (a secondary trackpad click) to hide the cursor and fly: mouse movement looks around, W/S move forward/back along the camera facing, A/D strafe, and Q/E move down/up in world Y. Release the button to leave fly mode. Hold Command on macOS or Alt on Windows while scrolling to pan in the view plane. Pinch does not control the camera, and the viewport suppresses the browser context menu during right-click use. G selects a grazing view and O restores the overview. Flight, orbit and pan preserve free camera height; only the overview preset anchors its focus above the terrain. CONFIG exposes error tolerance, LOD colors/grid, a camera tour and the stable detail region.

## Author to runtime
The [source EXR](https://github.com/trentpolack/worldcreator/blob/main/dragon_pit_01/HeightMap.exr) is Trent's MIT-licensed World Creator export. The original is 268,566,805 bytes and is deliberately excluded from this repository. Its SHA-256 is `f64f35d93079db360de0df5740cdbd0c1d16e18dd776b274eb98c7c1257cb448`.

```sh
python3 -m venv /tmp/joy-terrain-python
/tmp/joy-terrain-python/bin/pip install OpenEXR==3.5.1 numpy==2.5.3
curl -L --fail https://media.githubusercontent.com/media/trentpolack/worldcreator/main/dragon_pit_01/HeightMap.exr -o /tmp/dragon-pit.exr
/tmp/joy-terrain-python/bin/python scripts/assets/compile-terrain.py /tmp/dragon-pit.exr joy-engine/examples/terrain/site/public/dragon-pit --channel Y --size 1025 --tile-cells 64 --extent 2048 2048 --vertical-scale 1000 --source-url https://github.com/trentpolack/worldcreator/blob/main/dragon_pit_01/HeightMap.exr
/tmp/joy-terrain-python/bin/python scripts/assets/test-terrain.py
```

The source has one `Y` float32 channel, data/display window `[0,0]`–`[8191,8191]`, and 67,108,864 finite values in `[0.08760054409503937,0.5539144277572632]`. The compiler inspects all channels before conversion and requires the height channel explicitly. It rejects nonfinite samples rather than silently filling or clipping them. MIT source notice is retained beside runtime data in `LICENSE-source.txt`; OpenEXR (BSD-3-Clause) and NumPy (BSD-3-Clause) are offline tools, not browser dependencies.

Demo dimensions are explicit example units: X/Z extent 2048 × 2048, Y = source height × 1000 with offset zero. They are not inferred physical meters. Source row zero maps to world negative Z, last row to positive Z, first column to negative X, last to positive X; no row flip or transpose is applied. This preserves source raster orientation; no unprovided compass orientation is inferred. The compiler globally resamples the full 8192-square raster to 1025-square using bilinear interpolation with endpoints preserved, then applies one uint16 range derived from the full source. The maximum quantization error is 0.003558 world units. Downsampling error relative to the 8192-square source is separate and is not included in the render LOD budget. Use a larger supported `--size` (up to 4097) if source-scale detail is required; rebuild bounds and errors with every asset change. No tile is renormalized independently.

## Reusable terrain contract
`loadTerrain(url)` and `decodeTerrain(manifest, binary)` produce an immutable-by-contract resident asset. Version 1 is a square power-of-two-plus-one grid, power-of-two leaf size (2–128 cells), row-major uint16 little-endian binary and explicit world scales. The manifest includes source inspection/digest, global quantization offset/scale, leaf bounds and monotone maximum triangle-approximation errors for every power-of-two stride. Its coarse quadtree aggregates leaf bounds/errors for future spatial traversal; v1 evaluates a bounded list of fixed quadtree leaves. It does not merge leaves into larger draw patches. Runtime has 256 patches and at most 2,097,152 triangles. It reuses one indexed 65 × 65 vertex lattice and seven index ranges rather than duplicating landscape triangle vertices. `heightSha256` records export integrity; the runtime validates format/length but does not recompute that digest.

`selectTerrain(asset, view)` uses geometric error and conservative distance to patch AABBs, plus a projected cell-size limit of 32 CSS pixels. CSS projection scale keeps DPI from changing LOD quality. Fractional LOD morphs heights to the next coarser triangle surface before switching indices. The parent surface includes reconciled boundary heights, so removed interior vertices converge to the stitched parent triangles even beside coarser neighbors. Shared edges use the coarser fractional neighbor level, so both evaluate the same linear boundary. Tile corners are source samples at every supported stride and remain invariant, including four-way corners. Height-only morphs preserve X/Z, enabling arbitrarily different neighbor resolutions without skirts. The target region pins finest resident detail and fades over an additional radius to avoid a hard transition. No source heights are rescanned per frame.

`TerrainRenderer(device, asset, colorFormat?)` borrows a Joy luma device and caller render pass. Await `ready()` before the first frame. `prepare(matrix, view, diagnostic)` must run before opening the render pass. Optional profiling uses `timing.begin(nowMilliseconds)` as render-pass properties and calls `timing.end()` after submission without awaiting it. `draw(pass)` does not clear, resolve or submit. `destroy()` releases all owned buffers/shaders/texture/pipelines once, including constructor rollback. The owner submits the device and releases it after terrain disposal. Terrain buffers are fixed after initialization; only uniforms change each frame. The optional timestamp owner lazily allocates and retains its small query staging buffers on the first sample. The demo owns its canvas/device and does not modify the vehicle playground or environment systems.

WebGL 2 performs CPU selection and uploads compact per-patch uniforms. WebGPU evaluates the same AABB/error policy in compute, reconciles shared edges in a second ordered dispatch, and emits compact descriptors plus indexed indirect commands consumed directly by rendering. There is no synchronous GPU readback or hardware tessellation. Both evaluate all resident leaves; frustum culling, leaf merging and streaming are not implemented. WebGPU triangle statistics show the explicit upper bound because the frame loop does not read selection back. CPU statistics report selected counts. CPU preparation/submission times are wall-clock work, not GPU execution time. Timestamp profiling samples the terrain render pass asynchronously at most twice per second when the backend exposes timestamp queries; it excludes compute selection and never blocks a frame. Unsupported or failed timing is labeled explicitly. Resident memory statistics cover terrain numeric arrays and owned GPU allocations, excluding borrowed framebuffer/depth attachments, driver overhead and JS object overhead.

## Integration boundaries
`sampleTerrain(asset, worldX, worldZ)` samples the stable finest resident triangle surface. Collision, wheel contact, road placement and gameplay must use authored/runtime height data with explicit scale, never camera-selected topology. This demo does not create a Cannon heightfield, drivable vehicles, roads or collision bodies. A road adapter must author its road/collision geometry consistently with this world coordinate contract and can pin render detail around vehicles; the pin is only a rendering policy.

The renderer takes a borrowed device/pass and optional color attachment format, so the independent environment/rendering work can compose it into its own scene pass without terrain owning atmosphere, post-processing or lighting resources. Current material is simple derivative-normal diffuse terrain coloring and display gamma. It is not integrated PBR/HDR, terrain shadowing or a large terrain material system. The JOY-EDITOR control states the offline workflow and the command to launch the separate editor; terrain authoring/editor integration is not implemented. Height editing would require re-exporting affected tile errors/ancestor bounds and updating GPU height regions; no editing API is claimed here.

## Validation
`npm run capture:example:terrain` starts an isolated random-port development server and Playwright Chromium browser (headed by default on macOS; temporary profile); `-- --built` uses the production build; screenshots stay in ignored `artifacts/captures/` and do not update site previews. Captures exercise both available backends, fly/orbit/pan/tour/near-ground movement, LOD visualization, tolerance changes and resize. Unsupported WebGPU adapter acquisition is reported explicitly; shader/compute errors fail the capture. The gallery is appearance evidence, not a hardware performance benchmark. The bundled macOS headless browser failed canvas presentation while its compute parity test passed; headed Chromium rendered both backends. Use `TERRAIN_HEADLESS=1` to reproduce the headless limitation or `TERRAIN_HEADED=1` elsewhere. Headed bundled Chromium and installed Google Chrome passed both backend captures on this Mac, including CPU/compute descriptor and indirect-command parity (maximum descriptor difference 0.000002061). Native Safari was not automated because its remote automation was not configured; Microsoft Edge was not installed. These remain unverified.

Core regressions live in `joy-engine/test/terrain.test.mjs`; offline exporter tests use synthetic plane/spike/nonfinite inputs. Root validation remains `npm run validate` as required by AGENTS.md.

The WebGPU path deliberately keeps indirect `firstInstance` zero and uses static per-draw uniforms for the patch index, so the optional `indirect-first-instance` feature is not required. `createGpuCanvasDevice` accepts optional supported WebGPU features; the demo requests timestamp queries. One-shot asynchronous descriptor/indirect readback in the development browser test compares CPU and compute results; no selection readback occurs in the runtime frame loop.
